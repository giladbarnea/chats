# Handoff: finish strict provider error handling

## Task overview

The user required this JSONL provider-resolution order:

1. Match a recognized native provider path.
2. Otherwise match Codex from a first `session_meta` object.
3. Otherwise match PI from a first `session` object with an integer `version`.
4. Otherwise exit with an error. Never assume Claude.

Path matching must win over conflicting content. Claude remains path-only because recent Claude sessions have no stable first object.

## Important discoveries

A local corpus found the PI header signature in 2,864 of 2,864 PI sessions and no Claude or Codex sessions. Codex consistently starts with `session_meta`. Claude first-entry types vary, so content detection would be unsafe.

The original failure came only from the external `/private/tmp/avidor/.../transcript.jsonl` path. PI’s own loader accepted its tree. Its final three Bash calls lack results, indicating an incomplete final turn, but this did not cause the failure.

An early shell-test fix implicitly remapped every JSONL fixture to Claude. That recreated the removed fallback inside the harness. The final harness instead requires each Claude fixture to call `claude_fixture` explicitly.

A max-thinking GPT-5.6 Sonnet peer review found one P2 issue and no others. `cmd_name` and `cmd_rm` let the new provider `ValueError` escape. The follow-up now catches both errors and covers clean status-1 exits without file changes.
