# Slice Six selection

Slice Six sharpens the existing native ASCII candidate scan for default case-insensitive search.

Current evidence selected this boundary. The exact real launcher compared the current gate with a proved transient single-gate reference on 381 Claude files. Each series used five fresh-process pairs with alternating implementation order.

For an impossible literal, the unprimed and primed medians fell from 1,646.9 and 1,659.2 ms to 895.4 and 887.9 ms. This saves 751.6 and 771.3 ms, or 45.6% and 46.5%.

For the real `Rust` hit, the medians fell from 2,693.7 and 2,703.9 ms to 1,643.2 and 1,632.3 ms. This saves 1,050.5 and 1,071.6 ms, or 39.0% and 39.6%. All outputs and exit codes matched byte-for-byte.

The prototype charged one complete current native file scan before applying each proved decision. It did not use a zero-I/O cache or microbenchmark.

Cwd probing ranked second. Its cached ceiling saved at most 223.7 ms unprimed and 202.2 ms primed. First-timestamp probing saved at most 204.3 and 176.9 ms. The selected gate gives 3.4 to 6.3 times their absolute savings.

This slice does not move Unicode case folding, regex confirmation, JSON decoding, provider parsing, semantic rendering, cwd extraction, timestamp scanning, or search orchestration to Rust.
